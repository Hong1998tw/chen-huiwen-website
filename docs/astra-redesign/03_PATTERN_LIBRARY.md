# Pattern library

## P01 任務入口
Observed Product: NYC311

User Problem: 先找到服務。How: 搜尋加服務目錄。Strength: 少一步。Weakness: 分類維護。Applicable/Adaptation: 採用：首頁常用入口。

## P02 機關與需求分流
Observed Product: Warren services

User Problem: 不知道找誰。How: 按問題分類再導向既有服務。Strength: 路徑清楚。Weakness: 過細會混淆。Applicable/Adaptation: 採用簡化版：聯絡／法律／陳情。

## P03 地點與主題獨立
Observed Product: ONS Census Maps

User Problem: 跨地點查議題。How: 兩組篩選保持 URL。Strength: 可分享。Weakness: 條件組合複雜。Applicable/Adaptation: 沿用並強化探索入口。

## P04 資料年份可見
Observed Product: ONS / DOT

User Problem: 辨識時間效力。How: 事件日期與資料日期分開。Strength: 不誤認最新。Weakness: 仍需編輯維護。Applicable/Adaptation: 採用：內容更新及歷程日期。

## P05 圖層來源
Observed Product: OneMap

User Problem: 理解地圖範圍。How: 來源與發布時間。Strength: 可追溯。Weakness: 不能替代逐案核驗。Applicable/Adaptation: 保留里界來源及代表點說明。

## P06 空間真實性
Observed Product: Helsinki 3D

User Problem: 了解精度。How: 說明來源與精度。Strength: 避免假精確。Weakness: 資料取得昂貴。Applicable/Adaptation: 採用原則、拒絕3D實作。

## P07 公開原文入口
Observed Product: DOT / ONS

User Problem: 自行查核。How: 頁內資料連結。Strength: 可驗證。Weakness: 原站可能失效。Applicable/Adaptation: 採用：詳情快速到來源。

## P08 手機漸進呈現
Observed Product: ONS

User Problem: 小螢幕閱讀。How: 先條件再資訊。Strength: 操作清楚。Weakness: 圖可能較深。Applicable/Adaptation: 採用：列表／地圖顯示切換。
